# 什么是智能电子书

**智能电子书**是一种以结构化概念为骨架、以可测量学习目标约束内容、以交互与反馈支撑练习的数字教材。

这个定义有三个关键词，每个都对应一种可以被检查的能力，而不是一种宣传口径。 #智能电子书

## 一、骨架：结构化概念

普通电子书的目录是「第几章第几节」，智能电子书的目录首先是一张概念图。节点是概念，箭头表示「要先懂 A 才懂 B」。目录只是这张图的一种排布方式。

一个最小的概念图长这样：

```json
{
  "nodes": [
    { "id": 1, "label": "什么是智能电子书" },
    { "id": 2, "label": "概念依赖" },
    { "id": 3, "label": "学习目标" }
  ],
  "edges": [
    { "from": 1, "to": 2 },
    { "from": 1, "to": 3 }
  ]
}
```

有了这张图，写作时就可以问一个非常具体的问题：**这一节用到的概念，是否都已经在前面出现过？** 这个问题能消灭教材里最常见也最隐蔽的错误——先修倒置。画图方法见 [[概念枚举与原子概念]]。

## 二、约束：可测量的学习目标

「了解函数」不是学习目标，「给定一次函数解析式，能画出图像并求出与坐标轴的交点」才是。学习目标的写法由布鲁姆分类约束，详见 [[布鲁姆六级与学习目标]]。它的作用是让每一节都有验收标准：写完之后可以自问，读者现在能做这件事了吗？

## 三、反馈：交互与练习

交互不是为了炫技，而是为了让读者的错误**可见**。一个能拖动参数、实时看到图像变化的模拟，比十行文字更能暴露「k 为负数时图像往哪边斜」这种误解。这类交互在本库中统称 MicroSim，做法见 [[MicroSim 设计原则]]。

## 与传统电子书的对照

| 维度 | 传统电子书 | 智能电子书 |
| --- | --- | --- |
| 组织单位 | 章节标题 | 概念节点与依赖边 |
| 质量判据 | 内容是否完整 | 概念是否覆盖且顺序正确 |
| 读者动作 | 阅读、翻页 | 阅读、操作、作答、得到反馈 |
| 可诊断性 | 弱 | 每个交互与题目都绑定概念 |

## 一个检验问题

> 如果把这本书的所有样式都去掉，只剩纯文本和链接，它还剩下多少「智能」？

如果答案只剩目录，那它还只是第 1 至 2 级的教材；如果答案里还有概念顺序、题目与概念的对应、可运行的模型，那结构已经长在内容里了。

<question>
有人说「我们的书每章都有小测验，所以已经是智能电子书了」。这个说法缺了什么？
答案：缺的是概念结构，以及测验与概念的绑定。有测验只说明具备交互，不代表书知道自己教了哪些概念、这些概念谁先谁后。
解析：测验若不能指向具体概念，就只能给出对错，无法诊断读者卡在哪一步。智能电子书要求测验结果能回填到概念图上，这也是 [[质检与发布]] 中「题目覆盖率」指标的来源。
</question>

## 小结

- 智能电子书的智能，来自对自身概念结构的知情；
- 三要素：结构化概念、可测量目标、可反馈交互；
- 判断标准可以落到一句检查：去掉样式之后，还剩下什么。
