# 质量度量与内容质检

**质量度量**是能被统计、能被比较的数字；**内容质检**是照着清单逐项判断。两者缺一不可：只有指标会漏掉语义问题，只有清单会陷入主观。 #质检发布

## 一、六项核心指标

| 指标 | 定义 | 建议阈值 |
| --- | --- | --- |
| 断链数 | 指向不存在页面的链接 | 0 |
| 未定义概念数 | 正文出现但无处定义的节点 | 0 |
| 目标覆盖率 | 有对应任务的章节目标比例 | ≥ 90% |
| 交互可用率 | 键盘可完成全部操作的交互比例 | 100% |
| 首屏体积 | 首屏 JS + 关键 CSS | 按部署环境设定，保持稳定 |
| 平均阅读中断点 | 读者最常离开的章节位置 | 逐版下降 |

指标不必多，6 项足够驱动修正。新增指标前先问：它会改变我们下周做什么吗？

## 二、质检清单

### 结构

- 依赖图无环，且每个节点从入口可达；
- 每章都有概念清单，新增节点不超过 8 个；
- 覆盖矩阵「未定义」列为空。

### 内容

- 每个概念第一次出现时有定义；
- 定义满足 [[术语与 ISO 11179 规范]] 的四条约束；
- 每章 3 至 5 条可测量目标，动词可观察；
- 每条目标至少对应一道题或一个交互。

### 交互

- 有预测、有操作、有解释；
- 键盘可完成全部操作；
- 减少动画模式下仍可理解。

### 技术

- 构建无错误，静态资源路径正确；
- 内部链接全部可解析，双链没有 broken；
- 页面在窄屏与低端设备上可用；
- 有明确的回滚点与版本记录。

## 三、构建期自动检查

最小做法是在构建脚本里加三步：

1. 收集所有笔记的 slug 与标题，建立解析表；
2. 扫描正文中的 `[[双链]]` 与站内链接，输出未解析列表；
3. 检查依赖图的入度与环，输出异常节点。

任何一步出现阻断项就让构建失败，避免把问题带到线上。

## 四、人工抽检

自动检查覆盖不了语义。每章随机抽 3 个位置，回答两个问题：

- 这里的概念是否已经定义过？
- 这里的练习是否真的对应本章目标？

抽检记录比「已检查」四个字有用得多，它能指出下一轮该修哪里。

质量指标显示断链为 0、目标覆盖率 95%，但读者反馈「第三章看不懂」。还应该检查什么？
答案：检查先修倒置与定义质量：第三章是否使用了后置章节的概念，或定义是否循环、过粗。
